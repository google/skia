In Ganesh, an error during a flush (e.g., a failed resource allocation, a promise image whose fulfill proc returns null, or a failed render task or submit) is now fatal: rendering stops at the first failure and the `GrDirectContext` is abandoned. The flush still reports failure (`fSuccess == false`, `GrSemaphoresSubmitted::kNo`) and the `GrFlushInfo` submitted/finished procs are still called, but any requested semaphores and surface state changes are not applied. Clients should check `GrDirectContext::abandoned()` after a failed flush and recreate the context. Flushes that fail only because semaphores were requested on a backend without semaphore support still return false without abandoning the context.
